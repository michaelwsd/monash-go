Before anything else

Calling the API

Everything except /health sits under /api/v1 and requires a Clerk session token. The backend verifies it locally with Clerk's RS256 public key, so there is no network call to Clerk per request and no session state on the server.

Every authenticated request
# the token comes from Clerk on the frontend
Authorization: Bearer <clerk_jwt>
Content-Type: application/json
Every error, one shape
{ "detail": "a Monash email address is required" }

The token must carry sub, email, full_name, exp and iss. A token missing any of them is rejected with the same 401 as an expired or forged one, deliberately: the caller learns that it failed, not which check caught it.

Interactive docs. The app serves Swagger at /docs and ReDoc at /redoc, but only when ENVIRONMENT is not production. Both are switched off on the deployed build.

Users

Identity and profile

post /api/v1/users/sync auth

Takes no body: everything it needs is in the token. Call it on every page load. On a first sign-in it creates the users row and the matching rewards row; afterwards it refreshes email and full_name if they changed in Clerk, and otherwise returns the row untouched. Safe to call repeatedly, including twice at once.

Request
POST /api/v1/users/sync
Authorization: Bearer <clerk_jwt>

// no body
200
{
  "id": "3f1c…",
  "email": "abcd0001@student.monash.edu",
  "phone": "",
  "full_name": "Alex Nguyen",
  "role": "passenger",
  "is_concession": false,
  "home_campus": null,
  "green_points": 0,
  "joined_at": "2026-08-29T04:12:55Z"
}
StatusWhen
401No bearer token, or it fails verification
403The token's email is not @student.monash.edu or @monash.edu
New users arrive incomplete. phone is an empty string and home_campus is null until the onboarding form calls PATCH /users/me. Treat both as "not set yet", not as bad data.
patch /api/v1/users/me auth

A partial update: send only the fields you are changing. Unknown fields are rejected rather than ignored, so a typo fails loudly instead of silently doing nothing. email and full_name are absent because Clerk owns them, and green_points because the rewards engine does.

Request body
{
  "phone": "0412 345 678",
  "is_concession": true,
  "home_campus": "clayton"
}
200
// the full updated user, same
// shape as POST /users/sync
FieldTypeRules
phonestringAustralian mobile or landline; spaces are stripped, so 0412 345 678 is stored as 0412345678
is_concessionbooleanSelects the myki fare in every cost comparison
home_campuscampusOne of the five campus values
StatusWhen
404No user row for this token; call /users/sync first
422Badly shaped phone number, unknown campus, or a field the schema does not allow
500Explicitly sending "phone": null, which is treated as an attempt to clear it
Known rough edge. Clearing the phone raises the base DomainError, which maps to 500. It is a client mistake, so 400 would be the honest code: InvalidInputError in user_service.update_profile would fix it. Omit the field entirely to leave the phone alone.
Vehicles

Cars and the reference dataset

post /api/v1/vehicles auth

Registers a car and, if the user was still a passenger, promotes them to driver. Owning a car is the first unambiguous signal that someone intends to drive.

There are two ways in. If the driver picked one of the suggestions you showed them, send its reference_id and the reference row wins for every field. Otherwise they typed it by hand: the backend looks for an exact match on make, model, year and fuel type, and uses the reference figure if it finds one.

Request body
{
  "make": "Toyota",
  "model": "Corolla",
  "year": 2020,
  "fuel_type": "petrol",
  "fuel_consumption": 7.1,
  "reference_id": null
}
201
{
  "id": "9a2e…",
  "make": "Toyota",
  "model": "Corolla XSE",
  "year": 2020,
  "fuel_type": "petrol",
  "fuel_consumption": 7.1,
  "created_at": "2026-08-29T04:20:10Z"
}
FieldTypeRules
make reqstring1 to 60 characters
model reqstring1 to 60 characters
year reqinteger1950 to 2100
fuel_type reqfuel_typepetrol, diesel, hybrid or electric
fuel_consumption reqfloatAbove 0, at most 30 L/100km, or 45 kWh/100km for electric
reference_idintegerOptional. Set it when the driver picked a suggestion
StatusWhen
400Consumption above the ceiling for that fuel type
404reference_id matches no reference row, or the caller has no user row
422Missing field, unknown fuel type, year out of range
The response can differ from what you sent. When a reference row matches, its make, model, year, fuel type and consumption replace the typed values, which is why the example above answers "Corolla XSE" to a request that said "Corolla". Render the response, not the form state.
A car missing from the dataset still registers. The reference data is Canadian, so MG, GWM, BYD, LDV, Chery, Haval and most utes are absent, around 12% of the 2025 Australian market. The typed fuel_consumption is used as given. Never make the lookup a precondition in the UI.

get /api/v1/vehicles/reference auth

Searches the 17,344-row reference table so the driver does not have to know their own fuel consumption. Narrow it as the form fills in: make alone, then make and model, then the year.

Request
GET /api/v1/vehicles/reference
      ?make=Toyota
      &model=Corolla
      &year=2020
200
[
  {
    "id": 4821,
    "make": "Toyota",
    "model": "Corolla XSE",
    "year": 2020,
    "fuel_type": "petrol",
    "engine_size": 1.8,
    "avg_consumption": 7.1
  }
]
QueryTypeRules
make reqstringAt least 1 character
modelstringOptional
yearintegerOptional, 1950 to 2100
Units depend on fuel_type. avg_consumption is L/100km for petrol, diesel and hybrid, but kWh/100km for electric. Label it in the UI by branching on the fuel type; treating an EV's figure as litres makes its running cost roughly ten times too low.
get /api/v1/vehicles/reference/similar auth

The fallback when the exact car is not in the dataset. It relaxes the search in three steps and returns the first step that finds anything, closest year first, capped at ten results. Each carries the reason it matched, which is meant to be shown: the driver is being asked to accept a car that is not quite theirs.

Request
GET /api/v1/vehicles/reference/similar
      ?make=Toyota
      &model=Corolla
      &year=2019
      &fuel_type=petrol
200
[
  {
    "reference": { "id": 4821, … },
    "match_reason": "same model, different year"
  }
]
TierRelaxes tomatch_reason
1Same make and model, any yearsame model, different year
2Similar model name, same fuel typesimilar model, same fuel type
3Same make and fuel typesame make and fuel type

All four query parameters are required here, unlike the plain reference search. An empty array means all three tiers came back empty: fall back to manual entry.

Errors

Status codes

Services raise domain errors and never HTTPException; one handler registered on the base class maps each to a status and returns {"detail": "…"}. 422 is the exception - it comes from FastAPI's own request validation and carries Pydantic's error list instead.

CodeErrorMeans
400InvalidInputErrorWell-formed, but breaks a business rule
401InvalidCredentialsErrorToken missing, malformed, expired, or not signed by Clerk
403PermissionDeniedErrorAuthenticated, but not allowed. Today: a non-Monash email
404NotFoundErrorDoes not exist, or the caller may not know that it does
422FastAPI validationBody or query does not match the schema
500DomainErrorA rule with no more specific subclass. Treat as a bug
502UpstreamServiceErrorGoogle Maps or Servo Saver failed, timed out, or refused us
